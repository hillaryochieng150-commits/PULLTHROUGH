# PULLTHROUGH — free starter website

This is a polished, responsive website prototype for a customer enquiry and follow-up product.

## Run it on your laptop

1. Extract `pullthrough_starter.zip`.
2. Open the folder.
3. Double-click `index.html` to open it in Chrome.
4. Click **Get started** and create a demo profile.
5. Try adding, editing, deleting and drafting follow-up messages for enquiries.

No install, build step, API key or payment is required to view the prototype.

## Included

- Responsive landing page
- Demo account flow (not real authentication)
- Local demo dashboard
- Add/edit/delete enquiry records
- Follow-up message draft copied to clipboard when supported
- Simple outcome metrics
- Clearly labelled ad-space previews
- AdSense integration placeholder
- Privacy and terms starter pages

## Important: what is NOT production-ready yet

- Login is a browser-only demo; it has no password or secure account system.
- Records are saved in local storage on one browser/device. They are not synced to the cloud.
- No real WhatsApp automation or payment integration is present.
- Ads are placeholders; no ad network is connected, and no ad revenue is generated.
- Privacy and terms pages are drafts, not final legal advice.
- `hello@pullthrough.example` is a placeholder and must be replaced.

Do not enter real or sensitive customer information into this prototype.

## Zero-budget next steps

1. Test the prototype with sample data and fix usability issues.
2. Choose a real brand name only after checking domain, company and trademark availability.
3. Publish a static landing page using a free hosting tier (for example, GitHub Pages). A static host can publish the marketing site, but it does not add secure accounts or a shared database.
4. Set up a backend such as Firebase or Supabase on an appropriate free tier. Configure authentication, database rules, access controls and backups before handling real user records.
5. Replace the demo authentication/storage in `script.js` with the backend. Never put private admin keys in browser code.
6. Complete and publish accurate privacy, terms, contact and cookie/consent disclosures for the jurisdictions you serve.
7. Apply to an ad network only after the public site has original content, working navigation, a real contact identity and policy pages. Approval is not guaranteed.
8. Test on mobile and desktop, then invite a small group of pilot users.

## AdSense placeholder

In `index.html`, the AdSense script is commented out intentionally. After approval, replace `ca-pub-XXXXXXXXXXXXXXXX` with the publisher ID supplied by Google and follow the current AdSense setup instructions. Do not click your own ads, encourage invalid clicks, or display ads in ways that confuse users.
